# Test Results

Two kinds of evidence: the unit suite, which needs no devices and runs on every push to `main` or
`develop` and on every pull request (GitHub Actions, Python 3.10–3.13), and live runs against Junos vMX
routers, listed with the code state they were run on.

## Unit Tests — 1258/1258 passed

`pip install -e '.[dev]' && pytest` from the checkout root (`develop` a39d9c9, 2026-10-27: the dialect /
transport / driver split of #80–#84, the store hardening, the `Fleet` library API, `--every`, profiles,
`h-ssh-store export`, `--connect-timeout` (#126) and the probe (#127)). The standalone review of `develop` (18
items, issues #23–#29, PRs #30–#36) added 110 regression tests; every one was run against the code
before its fix and failed there.

The suite is laid out by layer where the package is: `tests/dialects` (what each dialect knows),
`tests/drivers` (the registry, the contract, the typed results), `tests/transports` (the CLI engine on
a scripted channel), and the transport, runner and CLI tests at the top level. `tests/fixtures/` holds
the packages the entry-point tests load, not tests: `hssh_dummy` registers `dummy@ssh` on the paramiko
transport, `hssh_broken` raises `ImportError` on import, `hssh_taken` claims names the registry already
has. No test opens a connection to a real device: paramiko, PyEZ and the `ssh` binary are faked, and
telnet runs against a scripted server on localhost. The probe before every run (#127) is answered by
the suite's own fake (`probed` in `conftest.py`: every box live, at once); its own tests take
`real_probe` and probe listeners on localhost.
